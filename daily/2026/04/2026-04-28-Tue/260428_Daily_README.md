## 💡 오늘의 핵심 인사이트

- 각 기능의 완료 일수를 `ceil((100-prog)/sp)` 로 먼저 변환하면 날짜 시뮬레이션 없이 풀 수 있다
- 배포는 항상 앞에서부터 순서대로 이루어지므로 큐(FIFO) 구조가 적합하다
- 묶음의 첫 번째 값(base)이 해당 묶음의 배포 기준일이 된다
- 새로운 묶음이 시작될 때 base를 갱신하지 않으면 잘못된 묶음이 만들어진다
- 루프 종료 후 마지막 묶음을 반드시 `answer.append(count)` 로 저장해야 한다

---

## 🔥 트러블슈팅 | Trouble Shooting

- **for문 안에서 popleft() 동시 사용** → 순회 중 큐 변경 시 오류 발생, while + popleft() 단독 사용으로 해결
- **base 갱신 누락** → 새 묶음 시작 시 base를 갱신하지 않으면 이후 비교가 모두 틀어짐
- **마지막 count 누락** → while이 끝난 뒤 마지막 묶음이 answer에 저장되지 않는 문제, 루프 밖에서 append로 해결

## 📊 복잡도

| 구분 | 방법 1 (for문 순회) | 방법 2 (deque) |
|------|------------------|----------------|
| 시간 | O(N) | O(N) |
| 공간 | O(N) | O(N) |

- 방법 1: days 리스트를 for문으로 순회하며 base와 비교, 명시적 큐 미사용
- 방법 2: deque를 사용해 popleft()로 앞에서부터 꺼내며 처리, 큐의 FIFO 특성을 명시적으로 표현

---

## 🔀 풀이 비교

- 두 방법 모두 시간/공간 복잡도는 동일하게 O(N)
- 방법 1은 구현이 단순하고 직관적
- 방법 2는 deque를 사용해 큐 자료구조의 의도를 명확히 표현하므로 스택/큐 문제 의도에 더 부합
