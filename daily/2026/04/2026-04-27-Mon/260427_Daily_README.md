## 💡 오늘의 핵심 인사이트

- 단순 `set` 차이로는 동명이인을 처리할 수 없다 → **빈도수(카운팅) 기반 접근**이 핵심
- `Counter(participant) - Counter(completion)` 에서 Counter 빼기는 결과가 0 이하인 키를 자동 제거한다
- 딕셔너리 `.get(key, 0)` 패턴은 키 존재 여부를 확인하지 않고 안전하게 카운팅할 수 있다
- 정렬 후 `zip` 비교는 "같은 인덱스에 같은 이름이 와야 한다"는 직관에서 출발한다
- 모든 쌍이 일치하면 participant의 마지막 원소가 완주하지 못한 선수다
- `Counter`는 내부적으로 방법 3(수동 딕셔너리 카운팅)과 동일한 로직을 수행한다

## 📊 복잡도

| 구분 | 방법 1 (정렬+zip) | 방법 2 (Counter) | 방법 3 (수동 딕셔너리) |
|------|------------------|-----------------|----------------------|
| 시간 | O(N log N) | O(N) | O(N) |
| 공간 | O(N) | O(N) | O(N) |

- 방법 1: `sort`가 O(N log N)으로 지배, zip 비교는 O(N)
- 방법 2: Counter 생성 O(N) + 차집합 O(N)
- 방법 3: participant, completion 각각 O(N) 순회

## 🔀 풀이 비교

| 구분 | 방법 1 (정렬+zip) | 방법 2 (Counter) | 방법 3 (수동 딕셔너리) |
|------|------------------|-----------------|----------------------|
| 핵심 아이디어 | 정렬 후 위치 비교 | Counter 차집합 | 수동 카운팅 |
| 코드 간결성 | 중간 | 최상 | 중간 |
| 시간복잡도 | O(N log N) | O(N) | O(N) |
| 추천 상황 | 라이브러리 제한 시 | 가장 Pythonic | 원리 이해, 면접 구현 |

```python
# 방법 1 핵심 - 정렬 후 zip 비교
for p, c in zip(participant, completion):
    if p != c:
        return p
return participant[-1]

# 방법 2 핵심 - Counter 차집합
answer = Counter(participant) - Counter(completion)
return list(answer.keys())[0]

# 방법 3 핵심 - 수동 딕셔너리 카운팅
count[p] = count.get(p, 0) + 1  # participant 카운팅
count[c] -= 1                    # completion 차감
```
