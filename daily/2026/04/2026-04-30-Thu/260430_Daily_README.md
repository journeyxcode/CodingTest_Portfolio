## 💡 오늘의 핵심 인사이트

- split() 대신 문자 단위 순회를 선택
  → split()은 연속 공백을 무시해 원본 공백 구조를 복원할 수 없음
- "직전 문자가 공백인가?"만 추적하면 단어 시작 위치를 판별 가능

## 🔥 트러블슈팅 | Trouble Shooting

- 연속 공백 처리: split() 사용 시 "hello  world" → ["hello", "world"]로
  공백 개수 정보가 손실됨. 문자 순회 방식은 공백도 result에 그대로 추가하므로
  연속 공백이 자동으로 보존됨
- 대소문자 혼재 입력(unFollowed): 무조건 lower() 처리로 통일되어 자동 해결

## 🔀 풀이 비교

| 구분 | 방법 1 (문자 순회) | 방법 2 (split 활용) |
|------|-------------------|-------------------|
| 핵심 아이디어 | 직전 문자가 공백인지 추적 | 단어 단위로 분리 후 capitalize() |
| 연속 공백 처리 | ✅ 자동 보존 | ❌ 공백 개수 손실 |
| 시간복잡도 | O(N) | O(N) |
| 공간복잡도 | O(N) | O(N) |
| 코드 간결성 | 보통 | 간결하나 엣지케이스 존재 |

```python
# 방법 2 — split(" ") 활용 (연속 공백 보존 가능하지만 엣지케이스 주의)
def solution(s):
    return " ".join(word.capitalize() for word in s.split(" "))
# ⚠️ capitalize()는 첫 글자 대문자 + 나머지 소문자를 한번에 처리
# ⚠️ split(" ")은 연속 공백 시 빈 문자열 ""을 원소로 포함 → join 시 공백 복원됨
# ⚠️ 단, capitalize()는 Python 내장이라 실제론 이쪽이 더 Pythonic
```

## 📌 재발 방지 & 다음에 적용할 점

- **문자열 분리 전에 공백 구조를 보존해야 하는지 먼저 확인**
  → split() / split(" ") 차이를 항상 의식할 것
  → split()은 연속 공백 무시 / split(" ")은 빈 문자열로 보존

- **"첫 글자 처리"가 필요한 문제는 prev 변수 패턴을 먼저 떠올리기**
  → 이전 상태만 기억하면 되는 경우, 별도 인덱스 없이 깔끔하게 해결 가능

- **숫자·특수문자에 upper()/lower() 적용 시 변화 없음** → 별도 분기 불필요
  → 타입 체크(isalpha()) 없이도 동작하는 경우가 많으니 먼저 시도해보기

- **result += char 패턴의 비효율성 인지**
  → 루프 내 문자열 연결은 매번 새 객체 생성 → 규모가 커지면 list + join() 권장
